00 — Executive Brief

Project Overview & Executive Brief

Understand GeetorusAI in 30 seconds or 2 minutes with zero buzzwords and 100% technical truth.

What is GeetorusAI Today?

GeetorusAI is an open-source, enterprise-grade Autonomous AI Agent Control Plane & Virtual Company Operating System. Rather than being a simple prompt-response chat wrapper, Geetorus provides a stateful orchestration substrate that allows engineering teams, founders, and enterprises to model, supervise, and deploy coordinated teams of autonomous agents organized as "Virtual Companies" (e.g., fullstack-forge, trail-of-bits-security).

❌ Conventional AI Chatbots & Wrappers

  • Single-turn prompt/response loops
  • Infinite retry loops that burn token credits
  • No human approval gates on destructive shell commands
  • Ephemeral memory; lost state on restart

✅ Geetorus Virtual Company OS

  • Multi-agent hierarchy (Tech Lead, Coder, QA)
  • Deterministic turn heartbeat daemon (heartbeat.ts)
  • Amber Gate: Sensitive actions pause for human verdict
  • 137 relational PostgreSQL tables via Drizzle ORM

⚡ Spoken Pitch Scripts for Hackathon Rounds

The 30-Second Elevator Pitch (Judging Round 1)

"Most AI tools today are single-agent chatbots that forget context, break production without asking, and have no accountability. Geetorus is a Virtual Company Operating System. We don't just prompt an LLM; we deploy an entire engineering department of coordinated agents—Tech Leads, Coders, and QA—governed by strict budget controls, human approval gates, and sandboxed Git environments. You assign a high-level goal, the agents decompose it into tracked issues, write code, run tests, and pause for your sign-off before anything touches production. It’s autonomous execution with enterprise safety."

The 2-Minute Technical Pitch (Systems & Architecture Judges)

"Under the hood, Geetorus is built as a hardened TypeScript monorepo powered by an Express API server, React 19 frontend, and Drizzle ORM backed by 137 PostgreSQL relational tables. Autonomous behavior is driven by a deterministic heartbeat scheduling engine (server/src/services/heartbeat.ts) rather than uncontrolled while-loops. When a task is dispatched, the orchestration engine provisions an isolated Git worktree lease and dispatches the turn to the active model adapter—supporting Claude 3.5 Sonnet, GPT-4o, and local Ollama. All tool interactions flow through an MCP-compliant Tool Gateway that enforces cryptographically signed execution tokens. If an agent attempts a sensitive shell command or git push, Geetorus traps the call in an 'Amber' approval state. Once approved by the operator in the UI, the agent resumes execution, verifies completion contracts, and records an immutable audit log."

01 — Market Problem

Product Purpose & The Single-Agent Trap

Why naive prompt loops fail in enterprise environments and how Virtual Companies solve it.

The 5 Systemic Failures of Conventional Agents

1. Runaway Token Costs (Lack of Financial Governance)

Traditional frameworks allow agents to loop recursively upon error. When an LLM encounters a syntax error or a failing test, it retries blindly until API credits are exhausted. Geetorus Solution: Enforces hard budget incident policies (packages/db/src/schema/budget_policies.ts) and cost tracking per turn.

2. The "God Agent" Anti-Pattern (Lack of Specialization)

Asking one single prompt to be the architect, developer, DB administrator, and tester leads to degraded reasoning and severe prompt drift. Geetorus Solution: Multi-Agent Virtual Companies where work is routed between distinct specialized agents with isolated roles.

3. Absence of Human Sign-off Gates (Dangerous Actions)

Autonomous agents executing destructive commands (deleting tables, pushing untested code to main) create enterprise liabilities. Geetorus Solution: First-class Amber Approval Gates requiring human operator verdicts before privileged tools execute.

4. Ephemeral State and Lost Context on Crash

Most agent tools store state in volatile RAM or flat files. If the process crashes, all work is lost. Geetorus Solution: Fully relational persistence across 137 PostgreSQL tables tracking turns, tool outputs, and work products.

5. Lack of Packaging & Repeatability

Setting up multi-agent teams typically requires writing brittle Python glue scripts. Geetorus Solution: Turnkey, version-controlled company packages (via companies.sh) that import with one command.

03 — Architecture Overview

Complete Multi-Layer System Architecture

From presentation clients to the Drizzle database and model adapter layer.

Architectural Layer Breakdown

Layer 1: Presentation & Client Applications

React 19 + Vite frontend (ui/src/App.tsx), Unified Commander CLI (cli/src/index.ts), and Turnkey Packaging CLI (companies-tool/src/index.ts). Consumes REST API endpoints and subscribes to real-time WebSockets.

Layer 2: API & Routing Layer

Express 4 HTTP server (server/src/app.ts) hosting 78 route modules under /api/*. Enforces Zod schema validation, actor authentication (actorMiddleware), and strict company tenancy isolation.

Layer 3: Orchestration & Turn Scheduling

Turn-based Heartbeat Daemon (server/src/services/heartbeat.ts). Acquires exclusive execution leases, tracks stall timeouts via task-watchdogs.ts, verifies financial budget limits, and triggers human approval gates.

Layer 4: AI Model Adapters & Tool Execution

13 model adapters under packages/adapters/ (Claude, OpenAI, Ollama, OpenRouter). Model tools pass through the Model Context Protocol (MCP) Tool Gateway (tool-gateway.ts) with HMAC-SHA256 signature verification.

Layer 5: Persistence & Encrypted Storage

PostgreSQL 16+ backing 137 relational tables via Drizzle ORM (packages/db/src/schema/*.ts). Bundles local zero-config embedded-postgres and an AES-256-GCM encrypted secrets vault.

05 — Execution Trace

End-to-End Execution Trace & Working Flow

Trace of a real user request ("Fix Auth Expiration Bug") from UI creation to verified commit.

Chronological 5-Phase Execution Flow

Phase 1: Boot & Daemon Awaken

startServer() in server/src/index.ts boots OpenTelemetry, checks migrations via applyPendingMigrations(), boots embedded PostgreSQL, mounts 78 routes, and starts heartbeatService.start() polling every 1,000ms.

Phase 2: Task Submission

Operator clicks "New Issue" in ui/src/pages/Issues.tsx. useIssues.ts calls POST /api/issues. Express route validates schema with Zod, inserts record into issues table, and broadcasts issue:created over WebSockets.

Phase 3: Heartbeat Turn & Worktree Claim

Heartbeat poller in heartbeat.ts detects runnable issue. workspaceRuntimeLeaseService.claimLease() locks the task, checks budgetService.assertBudgetAvailable(), creates a local Git worktree (.geetorus/worktrees/iss_101), and assembles system prompt context.

Phase 4: Tool Execution & Amber Gate Approval

LLM generates tool intent file_read (executed immediately in worktree). Agent patches code and calls git_commit. Policy classifies action as REQUIRE_APPROVAL. Turn pauses, UI displays amber approval card. Operator reviews diff and clicks Approve.

Phase 5: Finalization & Audit Commit

Turn resumes, commits git change, releases workspace lease, logs token expense in cost_events, marks issue status as completed, and notifies connected clients via live-events-ws.ts.

07 — Symbol Reference

Functions, Classes, and Responsibilities

Core functions, signatures, callers/callees, and security guards.

startServer(): Promise<HttpServer>

File: server/src/index.ts

Orchestrates the complete bootstrap sequence: boots OpenTelemetry, checks migrations via inspectMigrations(), initializes embedded PostgreSQL on dynamic port, mounts Express app via createApp(), binds WebSockets, and starts background heartbeat turns.

createApp(db: Db, config: AppConfig): Express.Application

File: server/src/app.ts

Express application factory mounting global middlewares (JSON 50MB limit, actorMiddleware, privateHostnameGuard), mounting 78 modular route handlers under /api/*, and registering static React UI handlers.

heartbeatService.start(): void

File: server/src/services/heartbeat.ts (29,391 lines)

Central turn scheduler polling every 1,000ms. Identifies runnable issues, claims exclusive runtime leases in execution_workspace_runtime_leases, checks budget thresholds, templates prompt context with renderGeetorusWakePrompt(), invokes active AI model adapter, and dispatches tool intents to the MCP gateway.

toolGatewayService.dispatch(request: ToolDispatchRequest): Promise<ToolDispatchResult>

File: server/src/services/tool-gateway.ts

Regulates all agent tool intents. Evaluates company tool access policy: if DENY, rejects immediately; if REQUIRE_APPROVAL, pauses turn and creates amber approval record in approvals table; if ALLOW, verifies HMAC signature with GEETORUS_TOOL_ACTION_SIGNING_SECRET and executes inside the workspace.

approvalService.decideApproval(id: string, decision: 'approved' | 'rejected'): Promise<Approval>

File: server/src/services/approvals.ts

Receives human operator review verdicts from POST /api/approvals/:id/decide. If approved, wakes up paused heartbeat turn and executes tool; if rejected, feeds operator rejection feedback back to agent context to allow autonomous replanning.
