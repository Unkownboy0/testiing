# 12 — Security, Privacy, and Vulnerability Audit

> **Target Venue**: AURVEXX’2026 Hackathon  
> **Methodology**: Defensive security architecture review of `server/src/`, `packages/db`, and tool gateway.

---

## 1. Security Architecture & Threat Model

Geetorus enforces a multi-layered defense-in-depth model designed specifically for autonomous agent control planes:

```
+---------------------------------------------------------------------------------------------------+
|                                  SECURITY CONTROLS TOPOLOGY                                       |
|                                                                                                   |
|  [Layer 1: Network & Perimeter]                                                                   |
|  • Private Hostname Guard (`private-hostname-guard.ts`): Blocks SSRF against AWS metadata/private IPs.|
|  • Trust Proxy Configuration (`trust-proxy.ts`): Strictly validates upstream reverse proxy headers.|
|                                                                                                   |
|  [Layer 2: Authentication & Multi-Tenancy]                                                        |
|  • Actor Scoping Middleware (`actorMiddleware`): Verifies session token / API key.               |
|  • Strict Company Boundary: Every query enforces `where(eq(schema.companyId, actor.companyId))`.  |
|                                                                                                   |
|  [Layer 3: Cryptographic Action Verification]                                                     |
|  • Tool Action HMAC Signer: Privileged tool calls must carry valid HMAC-SHA256 signature.         |
|  • AES-256-GCM Vault: API keys stored encrypted in `company_secrets` table.                      |
|                                                                                                   |
|  [Layer 4: Execution Containment]                                                                 |
|  • Path Traversal Guard (`portable-path.ts`): Canonical path validation prevents directory escape.|
|  • Amber Gate Approval Engine: Sensitive tools pause and require explicit human operator verdict. |
|  • Log Redaction Engine (`log-redaction.ts`): Masks API keys and tokens from stdout and logs.     |
+---------------------------------------------------------------------------------------------------+
```

## 2. Security Audit Findings & Risk Register

| ID | Category | Verified Finding | Risk & Impact | Severity | Implementation Evidence | Remediations / Mitigations |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **SEC-01** | Secret Config | Weak default `GEETORUS_SECRET_KEY` in `.env.example` | High if deployed to production without generating a unique 32-byte key. | **Medium** | `.env.example:L9` | Server startup check should enforce minimum entropy when `NODE_ENV=production`. |
| **SEC-02** | Local Sandbox | Host process privilege in local worktree mode | In local mode, shell commands run with Node.js user permissions. | **High** | `services/execution-workspaces.ts` | Governed by MCP tool allowlist + Amber Approval Gate; recommend Docker/e2b for untrusted models. |
| **SEC-03** | Injection | Prompt injection in issue descriptions | Malicious user input could attempt to jailbreak agent persona. | **Medium** | `services/heartbeat.ts` | System prompt isolates task description from instructions; tool execution is strictly gated by policy. |
| **SEC-04** | SQL Injection | Zero raw SQL concatenation | SQL injection risk is completely mitigated by Drizzle ORM. | **None (Resolved)** | `packages/db/src/schema/*.ts` | All queries use parameterized queries generated by Drizzle ORM. |
| **SEC-05** | SSRF | Outbound HTTP requests from agent tools | Agent calling internal loopback (e.g., `http://169.254.169.254`) | **Low (Mitigated)** | `middleware/private-hostname-guard.ts` | `privateHostnameGuard` blocks requests to private IPv4 ranges and cloud metadata IPs. |
| **SEC-06** | Data Leakage | Sensitive tokens logged to console | Raw API keys exposed in server stdout / telemetry. | **Low (Mitigated)** | `server/src/log-redaction.ts` | RegEx scrubber automatically masks Anthropic, OpenAI, GitHub, and bearer tokens. |

## 3. Privacy & Compliance Policies

* **Zero Data Retention on Embeddings**: Since vector memory is not yet persisted to third-party vector databases, all data remains in the self-hosted PostgreSQL database.
* **Tenant Isolation**: Cross-tenant data leakage is structurally impossible at the ORM layer because all queries filter by `companyId`.
* **Telemetry Opt-Out**: Server instrumentation (`telemetry.ts`) transmits only sanitized error crash reports; telemetry can be disabled by omitting OTLP endpoints.
